# H-37 — The mark is applied on a robust quorum or a per-refresh deadline; one slow provider cannot delay the aggregate past the staging window

*Source: [hardening-plan-2026-09.md](../hardening-plan-2026-09.md) · Wave 4 (backend upgrade #4: oracle fan-out) · findings F34 · LOW, structural · filed 2026-09-03 from the 2026-09-02 scan, re-verified against `f3fbcf6`.*

`class: architecture` · `touches: backend, tests` — `after: H-11`, `after: H-23`

**Mechanism.** `refreshMultiSourcePrice` (`:15988-16005`) dispatches eight futures then awaits
each in order; `fetchFromSource` (`:14435-14446`) has no timeout (the IC API offers none — only
`max_response_bytes`); `_priceRefreshInFlight` (`:15560`, `:16139-16182`) holds across
sequential per-pool refreshes; `_geptorInFlight` TTL 60 s. One provider that trickles its body
controls the cadence of every mark: staged orders miss `DEFERRED_EXPIRY_NS` (15 s) and fall to
the users-only pass with the AMM (~58% of the book) sidelined, FOKs killed, marks one timeout
stale. Motoko cannot select on or abandon an `await`, so this is a restructure: per-source
self-calls record into a per-(asset, epoch) accumulator; the first completion to see
`minSources()` with acceptable dispersion (or a timer deadline well under 15 s) runs
`aggregateByQuote` → `applyFreshAggregate` → requote → release; late readings attach for
observability only; both in-flight guards release on quorum/deadline.

**Fix criteria.** As above. `lastAggregates` type unchanged if readings stay `[Reading]`; no
candid change unless `getPriceFeedStats` gains fields. Needs a dev hook (`devStallSource`) in the
mock route to test on a local replica.

**Verify.** One non-answering source in the fan-out: the mark still advances within the staging
window; `PriceFeed.test.mo` partial-set aggregation; `test_oracle_*.sh` green; live: staged
releases keep landing within ~2 s during a deliberate provider outage.

The decision is pure (`PriceFeed.fanoutRecord` / `fanoutClose`, unit-pinned): the FIRST arrival to see `robustQuorum` survivors with dispersion within the 50bps gate runs `#finalize(#quorum)`; the last arrival `#complete` (failed readings count toward completion, never toward the quorum); the heartbeat's sweep (`sweepPriceFanouts`, every beat while a fan-out exists, ABOVE the pause gate — it only completes fetches already dispatched, which is exactly what the in-order awaits it replaced did under a pause) closes an open fan-out at `PRICE_FANOUT_DEADLINE_NS` = 8s `#deadline`; an awaiting caller whose whole fleet returned closes `#drained`. `finalizePriceFanout` (whichever message reaches the decision; synchronous, no awaits) compares the epoch BEFORE every side-map write (abandons unwritten, guards released, the admin fetch reports it — the W4-13/#55 property, re-pinned in hygiene §6j/§6y on the new structure), aggregates per quote (`aggregateByQuote`, unchanged), writes `lastAggregates` / `_lastQuoteSignal` / the health edge, applies for every attached market through the SAME accept gate (`applyFreshAggregate` — floor, breaker, XRC fallback — with the fan-out's dispatch clock as the release reference, H-23), runs the GEPTOR's post-apply sequence (requote + `processDeferredSwaps`) for markets a GEPTOR attached, and releases both in-flight guards matched to the arm/stamp that dispatched (`_geptorInFlight` only if the entry is still OUR `armedAt`; the shared `_fetchInFlight` stamp — the tick's or the admin fetch's — only through `clearFetchInFlight` while it is still OUR dispatch clock: the #52.6 straggler shape, and the merge fold of main's `3088525590` (the admin fetch stamps the map) + `1788535668` (per-writer guarded clears, no whole-map clear) — both subsumed by the fan-out's single release site, re-pinned in hygiene). Late readings ATTACH (`attachLateReading`: `getLastAggregate` + the quote signal refreshed with the full fleet, keeping the finalization's clock, only while the fan-out is still the asset's latest and its epoch is live) and never re-apply. `refreshInFlight` is DERIVED from the open fan-outs — the W4-13 one-owner flag no longer exists, so there is nothing to latch. **Callers.** `tickPriceRefresh` dispatches every stale pool's fleet at once (one fleet per asset — a stale pool JOINS the asset's open fan-out and takes its earlier dispatch clock, the conservative side of H-23), no awaits, no sequential hold; the GEPTOR (`geptorFetchAndSweep`, now an `async*` dispatched inline in `processGeptorDue`'s message so arm and dispatch commit together) and the admin fetch own their fan-outs — a fleet dispatched before an arm could not release the entry that armed it; `fetchAndSetRefPrice` awaits its own eight futures, drains, and reads its market's outcome (`#ok(px)` / the pend text / the rejection / the abandonment). A stale-open fan-out (still open at 2× the deadline — a finalization that trapped on every retry) is reaped at the next dispatch/sweep with its guards released; finalized ones are retained 120s for late arrivals. **Deviation from the brief, recorded:** the quorum is `PriceFeed.robustQuorum(total, floor)` = max(floor, majority) = 5 of 8, not the bare `minSources()` (3): the trim locates the cluster with a median and a MAD and its breakdown point is what bounds the mark, so finalizing on the three FASTEST venues would hand the mark to whichever pair answers first — the dispersion gate bounds that damage, the majority removes it; the DEADLINE, not the quorum, is the latency bound (a fleet that cannot reach a majority still closes on `#complete` when the failures report, or at 8s when one hangs — measured: 10s from staging to close with four sources stalled, 2s with one).
